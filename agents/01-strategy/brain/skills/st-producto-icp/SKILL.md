# Pasos 1 y 2 · Producto → cliente ideal

| | |
|---|---|
| **Consume** | La reunión del día 1 · la web, el catálogo y las redes del cliente · la ficha de oferta |
| **Produce** | `01-estrategia/producto.md` (nodo `producto`) y `01-estrategia/icp.md` (nodo `icp`, `viene_de: [producto-…]`) |
| **Herramienta** | El perfil del cliente ideal del OS: el agente propone, el CEO corrige encima |

## 1 · El producto

| Qué se anota | Cómo |
|---|---|
| **Qué vende** | Cada producto o servicio, en palabras del comprador |
| **Precio y ticket** | Leído de la web o del cliente, con fuente. `[dice el cliente, sin verificar]` si no hay prueba |
| **La ecuación de valor** | Resultado soñado × probabilidad percibida ÷ (tiempo + esfuerzo). Se sube el valor con más prueba, menos tiempo y menos esfuerzo, **no bajando el precio** |
| **Qué lo hace distinto** | El mecanismo y las pruebas que lo sostienen |
| **Contra quién compite** | 3 a 5 alternativas reales que el comprador considera *(Firecrawl, AdWhispr)* |

🛑 **La oferta (qué se vende, en qué paquetes y a qué precio) solo se toca en Brand Foundation y en
Growth Partnership.** En Brand Growth se anota como está y se trabaja el mensaje.

## 2 · El ICP — los criterios

| Criterio | Pregunta |
|---|---|
| **Facturación mensual** | ¿Cuánto factura quien puede pagar esto sin sufrir? |
| **Ticket promedio** | ¿Cuánto vende por venta? |
| **Frecuencia de ventas** | ¿Cada cuánto vende? |
| **Demanda** | ¿Alta? Se prefiere demanda que ya existe |
| **Ciclo comercial** | ¿Rápido? Ciclos largos piden outbound y más paciencia |
| **Margen** | ¿Le alcanza para pagar el producto y que le quede? |
| **Capacidad** | ¿Aguanta más demanda sin romperse? Si no, la capacidad va primero |
| **Decisor** | ¿Quién firma? ¿Es quien ve el contenido? |
| **Industrias y perfiles** | Las que calzan con todo lo anterior, aunque el cliente no las haya pensado |
| **Dónde vive** | Geografía y canales: dónde pasa el tiempo y a quién le cree |

**La regla guía** es editable por producto y se escribe arriba del perfil: *p. ej. «el cliente
factura ~10× el precio del producto»*. Se usa para descartar rápido, no para decidir sola.

## 3 · Cómo se elige

1. **Se proponen 2 a 4 perfiles candidatos**, cada uno con los criterios llenos y su fuente.
2. **Se descarta** el que no pasa la regla guía o no tiene margen.
3. **Se elige uno principal** y, si hace falta, uno secundario. El resto queda anotado como
   descartado, con el porqué.

## 4 · Antes de cerrar

- [ ] Cada precio y cada número tiene fuente o etiqueta
- [ ] El ICP tiene los diez criterios; los vacíos dicen `⚠️ SIN DATOS`
- [ ] La regla guía está escrita y el perfil la cumple
- [ ] El nodo `icp` nace `hipotesis`; lo aprueba el CEO en el gate de ① Strategy
