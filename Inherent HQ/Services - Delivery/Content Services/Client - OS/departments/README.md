# Sistema operativo de entrega

Este folder tiene dos tipos de documentos que se complementan, pero no son lo mismo.

## 1. Operación inherente por área

Explica **cómo funciona el trabajo** dentro de cada departamento para llegar a un resultado: el flujo, las decisiones, las herramientas y los entregables.

No busca decirle a una persona cómo debe pensar. Define un sistema de trabajo que permite a un equipo coordinarse, repetir lo que funciona y detectar dónde se pierde calidad.

Cada documento de operación debe incluir:

- Objetivo del área y resultado esperado.
- Flujo de trabajo: desde el brief hasta la entrega y aprendizaje.
- Decisiones y aprobaciones necesarias.
- Herramientas que apoyan el flujo.
- Entregables, estándares de calidad y métricas.
- Dependencias: qué recibe de otras áreas y qué les entrega.

Ejemplo: Growth puede operar con un flujo de hipótesis → landing page → medición → experimento → aprendizaje. Sus herramientas podrían ser Webflow, HubSpot, GA4 y un gestor de tareas. Las herramientas habilitan el flujo; no sustituyen el criterio.

## 2. Roles, habilidades y estructura

Explica **quién hace posible la operación**: la jerarquía, las responsabilidades de cada puesto y las habilidades necesarias para hacer buen trabajo.

Cada documento de roles debe incluir:

- Cabeza del área: responde por dirección, calidad y resultado.
- Leads o managers: convierten la dirección en prioridades y coordinación diaria.
- Especialistas o ejecutores: realizan el trabajo técnico y producen los entregables.
- Responsabilidades y límites claros de cada rol.
- Habilidades necesarias: estratégicas, creativas, técnicas y de colaboración.

La jerarquía no existe para crear burocracia. Existe para que haya claridad sobre quién decide, quién coordina, quién ejecuta y quién responde por el resultado.

## Principio central

Tener herramientas, plantillas o automatizaciones no garantiza trabajo de calidad.

La calidad nace de la combinación de:

1. Roles bien definidos.
2. Habilidades reales en las personas.
3. Divisiones de responsabilidad claras.
4. Jerarquía útil para decidir y revisar.
5. Un flujo operativo que conecte el trabajo con el resultado.

El sistema operativo define **cómo se mueve el trabajo**. La estructura de roles define **quién lo piensa, decide, coordina y ejecuta**. Ambos deben diseñarse juntos, siempre al servicio de mejores resultados para el cliente.
